## 3. Luồng Request (Middleware Pipeline)

File: src/index.js · src/middleware/auth.js · src/middleware/permission.js · src/rate-limiting.js

### 3.1 Sơ đồ luồng toàn bộ (Admin Route)

Hình 2. Request Middleware Pipeline (Admin Route) — 9 bước xử lý

1. app.use(cors()) - CORS headers
2. app.use(express.json()) - Parse body
3. app.use(morgan()) - Request logging
4. app.use(rateLimiter) - Rate limiting check
5. app.use(auth) - JWT validation (nếu cần)
6. app.use(permission) - Permission checking
7. app.use(restrictToAllowedDomains) - Domain whitelist
8. app.use(proxyMiddleware) - Forward to service
9. Error handling - Catch & format error

### 3.2 Header inject khi forward sang microservice

| Header | Source | Value | Purpose |
| --- | --- | --- | --- |
| X-User-Id | req.user.id | UUID | User identity |
| X-User-Role | req.user.role | string | User role |
| X-Forwarded-For | client IP | IP | Original client IP |
| X-Forwarded-Proto | request protocol | http/https | Protocol |
| X-Request-Id | generated | UUID | Tracing ID |
| Content-Length | recalculated | number | Body size |

⚠️ OMS proxy: nếu middleware đã parse/modify body, req.rawBody được dùng để rewrite lại Content-Length — tránh body bị truncate khi forward.

### 3.3 Rate Limiting — logic chi tiết

| Endpoint | Limit | Window | Bypass Condition |
| --- | --- | --- | --- |
| /api/auth/login | 5 | 15 min | None |
| /api/admin/\* | 100 | 15 min | IP in IP\_GK |
| /api/payment/\* | 50 | 1 min | apiKey valid |
| /api/\* (default) | 1000 | 1 hour | None |

Rate limit check: (current\_count) \> limit → return 429 Too Many Requests

Store in Redis: ratelimit:{userId}:{endpoint} with TTL = window duration

## 4. Hệ thống Authentication & Security

File: src/middleware/auth.js · src/middleware/permission.js · src/lib/jwt.js · src/lib/cipher.js

### 4.1 Tổng quan các middleware bảo mật

| Middleware | Target Routes | Logic |
| --- | --- | --- |
| adminRequired | /api/admin/\* | JWT decode & validate, check expiry |
| staffRequired | /api/staff/\* | JWT valid & role = staff/admin |
| permission | Admin/staff routes | Check req.requiredPermission in DB |
| keyProxy | /api/payment/_, /api/partner/_ | Decrypt X-API-Key, check timestamp |
| restrictToAllowedDomains | All routes | Check Origin/Referer in whitelist |
| checkInternalGK | DELETE routes | Check IP in env IP\_GK (JSON array) |

### 4.2 JWT Authentication Flow (adminRequired)

Hình 3. JWT Authentication Flow (adminRequired)

1. Extract token từ Authorization header: Bearer \[token\]
2. Verify signature bằng JWT\_SECRET
3. Decode payload → req.user = decoded
4. Check token expiry (ngày, không giờ)
5. Query DB: Staff.findByUsername(req.user.username)
6. Return 401 nếu user không tồn tại hoặc bị deactive
7. Attach req.user với full staff data

⚠️ Token expiry check bằng ngày (setHours(0,0,0,0)), không phải exact timestamp. Token tạo lúc 23:59 hôm qua sẽ invalid từ 00:00 hôm nay.

### 4.3 keyProxy — Timestamp-based API Key

Client tạo key: Encrypter(Date.now().toString()) — mã hóa timestamp hiện tại

Backend: Decrypter(X-API-Key) → parseInt → check Date.now() - parsedKey ≤ 60,000ms

Mục đích: ngăn replay attack — key chỉ valid trong 60 giây kể từ lúc tạo

⚠️ Client phải generate key mới cho mỗi request. Không cache key giữa các lần gọi API.

### 4.4 Permission System — cấu trúc

Mỗi admin route được đặt trước một permission middleware để declare loại quyền cần có:

app.put('/api/v2/coupons', permission.updateCoupons, adminRequired) ↑ Sets req.requiredPermission = 'updateCoupons' adminRequired sẽ query DB: Permission WHERE actionName = 'updateCoupons'

Cấu trúc phân quyền trong database:

Staff  ──(staffgroup)──►  Group  ──(grouppermission)──►  Permission { id, username, email }   { name }                       { actionName }

Danh sách permission nhóm theo module:

| Module | Permission | Description |
| --- | --- | --- |
| Coupon | createCoupons | Tạo coupon |

## 7. Ghi chú quan trọng

- Tất cả DELETE requests đều bị log vào Lark và kiểm tra IP whitelist (checkInternalGK) — bất kể endpoint nào.
- JWT token expiry check theo ngày (setHours(0,0,0,0)) — token tạo 23:59 hôm qua invalid từ 00:00 hôm nay. Không phải expiry theo giờ.
- keyProxy API key chỉ valid 60 giây — client phải generate lại mỗi request.
- Rate limiting bypass: request từ IP nằm trong env IP\_GK (JSON array string) sẽ skip tất cả spam checks và limiter.
- Sequelize paranoid mode: tất cả model dùng soft delete — raw Knex SQL query phải tự thêm WHERE deletedAt IS NULL.
- CORS được set origin: '\*' toàn cục — restrictToAllowedDomains là middleware riêng biệt chỉ áp dụng cho các route được chỉ định.
- OMS proxy raw body: khi middleware đã parse/modify body, phải dùng req.rawBody để rewrite Content-Length header — nếu không body có thể bị truncate.
- Trade-in proxy (cacheSpam): kết quả check spam được cache Redis — cùng IP trong window sẽ nhận response từ cache, không re-execute handler.
